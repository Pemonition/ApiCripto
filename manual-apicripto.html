Manual da ApiCripto

Como cadastrar uma corretora, colocar ativos nela e trazer preço real do mercado — na ordem em que a API espera. O documento irmão, ApiCripto por dentro, explica como ela foi construída; este aqui explica como se usa.

01 — modeloOs três conceitos

Tudo na API gira em torno de três coisas encaixadas uma dentro da outra. Entender essa ordem evita 90% dos erros de uso, porque a API recusa qualquer tentativa de pular etapa.

Primeiro
Corretora
Onde o ativo é negociado. Binance, Mercado Bitcoin, Foxbit.
/api/corretora
Depois
Ativo
Um par negociado dentro de uma corretora: BTCUSDT, ETHBRL.
/api/ativo
Por fim
Cotação
O preço do ativo num instante. Vira histórico — nunca é sobrescrita.
/api/ativo/{id}/cotacao

O mesmo símbolo pode existir em duas corretoras (BTCUSDT na Binance e na Foxbit são registros diferentes, com preços diferentes), mas não pode aparecer duas vezes na mesma. Cada ativo carrega ainda o último preço como campo próprio, atualizado toda vez que uma cotação nova entra — é isso que faz o filtro de faixa de preço responder rápido.

O campo que decide tudo

A corretora tem um campo codigoIntegracao. Com o valor "BINANCE", os ativos dela podem buscar preço sozinhos. Com null, a corretora existe normalmente, mas o preço dos ativos dela só entra na mão. É o interruptor entre "sincroniza" e "lançamento manual".

02 — execuçãoSubir a API

Pelo terminal, de dentro da pasta do projeto:

terminalApiCripto/ApiCripto
# o banco e os dados de exemplo são criados no primeiro run
dotnet run --launch-profile http

Pelo Rider ou Visual Studio: abra ApiCripto.sln, escolha o perfil http e rode. O navegador abre no Swagger sozinho.

Na primeira execução a API cria o arquivo apicripto.db, aplica a migration e insere dados de exemplo: 2 corretoras e 7 ativos. Nas próximas, o seeder vê que já tem gente lá dentro e não faz nada. Para voltar ao estado inicial, pare a API, apague o .db e rode de novo.

Três formas de conversar com ela

  • Swagger em /swagger — lista todos os endpoints com formulário pronto. A raiz redireciona para lá.
  • Arquivo ApiCripto.http — 33 requisições na ordem deste manual, com "Send Request" acima de cada uma. Funciona no Rider, no Visual Studio e no VS Code com a extensão REST Client.
  • curl, Postman, Insomnia — é uma API REST comum, sem chave e sem cabeçalho especial.

03 — passo a passoDo zero ao primeiro preço

A sequência abaixo é a mesma que a API exige internamente: cada passo depende do anterior ter acontecido. Se você tentar o passo 2 sem o 1, recebe 400 dizendo qual corretora não existe.

1

Cadastrar a corretora

Só nome é obrigatório. Preencha codigoIntegracao com "BINANCE" se quiser que os ativos dela busquem preço sozinhos.

POST/api/corretora
{
  "nome": "Binance",
  "site": "https://www.binance.com",
  "paisSede": "Malta",
  "codigoIntegracao": "BINANCE"
}
201 Createdguarde o id
{
  "id": 1,
  "nome": "Binance",
  "site": "https://www.binance.com",
  "paisSede": "Malta",
  "codigoIntegracao": "BINANCE"
}
2

Cadastrar o ativo dentro dela

O simbolo precisa ser exatamente o par como a corretora o chama — BTCUSDT, não BTC/USDT nem bitcoin. É essa string que vai ser mandada para a Binance na hora de sincronizar. O tipo aceita Cripto, Stablecoin ou Token, e monitorado diz se ele entra na sincronização em lote.

POST/api/ativo
{
  "simbolo": "BTCUSDT",
  "moedaBase": "BTC",
  "moedaCotacao": "USDT",
  "tipo": "Cripto",
  "monitorado": true,
  "corretoraId": 1
}
201 Createdainda sem preço
{
  "id": 1,
  "simbolo": "BTCUSDT",
  "ultimoPreco": null,
  "variacao24h": null,
  "atualizadoEm": null,
  "corretoraId": 1
}

Repare nos três null: preço não é algo que você informa no cadastro. Ele só aparece depois do passo 3.

3

Trazer o preço

Aqui o caminho se divide, e o que decide é o codigoIntegracao da corretora do passo 1.

Corretora integrada — automático

POST/api/sincronizacao/ativo/1
// sem corpo. A API consulta a Binance e grava a cotação.
{
  "id": 20,
  "preco": 78504.38000000,
  "variacao24h": -0.883,
  "precoMaximo24h": 79485.00000000,
  "precoMinimo24h": 77620.01000000,
  "fonte": "Binance",
  "ativoId": 1
}

Para atualizar todos os ativos monitorados de uma vez, use POST /api/sincronizacao sem corpo. Ele devolve um relatório com quantos deram certo e o erro de cada um que falhou — uma falha isolada não derruba o lote.

Corretora sem integração — manual

POST/api/ativo/6/cotacao
{
  "preco": 421500.00,
  "variacao24h": -0.51,
  "precoMaximo24h": 425000.00,
  "precoMinimo24h": 418200.00,
  "volume24h": 12500.00
}

Os dois caminhos terminam no mesmo lugar: uma linha nova no histórico e os campos de preço do ativo atualizados. Nada é sobrescrito — cada cotação fica guardada com a hora em que foi capturada.

4

Consultar

Agora o ativo responde com preço, e os filtros passam a fazer sentido:

GETconsultas típicas
# tudo que tem "btc" no símbolo, do mais caro para o mais barato
/api/ativo?simbolo=btc&ordenarPor=preco&desc=true

# criptos da corretora 1 acima de US$ 1.000
/api/ativo?corretoraId=1&tipo=Cripto&precoMin=1000

# as 50 cotações mais recentes do ativo 1
/api/ativo/1/cotacao?limite=50

04 — referênciaTodos os endpoints

Corretora

RotaO que fazRespostas
GET /api/corretoraLista todas.200
GET /api/corretora/{id}Uma corretora.200 404
POST /api/corretoraCadastra.201 400
PUT /api/corretora/{id}Atualiza o cadastro inteiro.204 404
DELETE /api/corretora/{id}Remove — só se não tiver ativos.204 400 404

Ativo

RotaO que fazRespostas
GET /api/ativoLista com os filtros da seção 5.200
GET /api/ativo/{id}Um ativo, com a corretora dele.200 404
POST /api/ativoCadastra numa corretora.201 400
PUT /api/ativo/{id}Atualiza o cadastro. Não mexe em preço.204 400 404
DELETE /api/ativo/{id}Remove o ativo e todo o histórico dele.204 404

Cotação

Rota aninhada: a cotação não existe fora de um ativo, e a URL diz isso.

RotaO que fazRespostas
GET /api/ativo/{ativoId}/cotacaoHistórico, do mais recente para o mais antigo. Aceita desde, ate e limite.200 404
GET /api/ativo/{ativoId}/cotacao/{id}Uma cotação específica daquele ativo.200 404
POST /api/ativo/{ativoId}/cotacaoLança preço na mão.201 400 404
DELETE /api/ativo/{ativoId}/cotacao/{id}Apaga uma cotação do histórico.204 404

limite vem 100 por padrão e para em 500, mesmo que você peça mais — um teto para uma consulta distraída não puxar o histórico inteiro.

Sincronização

RotaO que fazRespostas
POST /api/sincronizacao/ativo/{id}Puxa o preço de um ativo na Binance.200 400 404 502
POST /api/sincronizacaoPuxa o preço de todos os ativos monitorados de corretoras integradas.200

São POST, e não GET, porque cada chamada escreve no banco: nasce uma cotação nova. GET, por contrato do HTTP, não pode ter efeito colateral — e pode ser cacheado por qualquer proxy no caminho.

O lote sempre responde 200, mesmo com falhas: o corpo traz totalConsiderados, sincronizados, comFalha e a lista item a item com o erro de cada símbolo que não veio.

05 — consultaOs filtros de ativo

Todos opcionais, todos combináveis entre si — cada um que você preenche estreita o resultado. Vão na query string de GET /api/ativo.

ParâmetroTipoO que fazExemplo
corretoraIdinteiroSó os ativos daquela corretora.?corretoraId=1
simbolotextoBusca parcial, ignora maiúsculas. btc traz BTCUSDT e BTCBRL.?simbolo=btc
tipotextoCripto, Stablecoin ou Token.?tipo=Stablecoin
precoMindecimalÚltimo preço maior ou igual.?precoMin=1000
precoMaxdecimalÚltimo preço menor ou igual.?precoMax=500000
monitoradobooleanoSó os que entram (ou não) na sincronização em lote.?monitorado=true
ordenarPortextosimbolo (padrão), preco ou variacao.?ordenarPor=preco
descbooleanoInverte a ordenação.?desc=true
Ativo sem preço não aparece na faixa

Um ativo recém-cadastrado tem ultimoPreco: null — e null não é maior nem menor que nada. Ele fica de fora de qualquer consulta com precoMin ou precoMax até a primeira cotação entrar. Não é bug: é a diferença entre "não tem preço" e "tem preço zero".

Combinar é só emendar com &. As stablecoins monitoradas da corretora 1, da maior variação para a menor:

GETfiltros combinados
/api/ativo?corretoraId=1&tipo=Stablecoin&monitorado=true&ordenarPor=variacao&desc=true

06 — diagnósticoQuando dá erro

Toda recusa vem com um corpo { "mensagem": "..." } dizendo o que aconteceu. O status HTTP diz de quem é a responsabilidade.

StatusQuando aconteceO que fazer
400 Símbolo repetido na mesma corretora; corretora inexistente no cadastro do ativo; campo obrigatório faltando ou fora do tamanho; DELETE de corretora que ainda tem ativos. A mensagem nomeia o culpado. Corrija o corpo e repita.
404 O id da URL não existe — ou a cotação existe, mas é de outro ativo. Confira o id numa listagem antes.
400 na sincronização O ativo é de uma corretora sem codigoIntegracao. Lance a cotação manualmente, ou preencha o código na corretora.
502 A Binance recusou ou não respondeu: símbolo que não existe lá, rede fora, limite de requisições. Não é falha da sua API — é a corretora. Confira o símbolo e tente de novo.
502 em tudo, de uma vez só

Se todos os símbolos falharem ao mesmo tempo, o problema é rede, não símbolo. A Binance bloqueia o api.binance.com por região em boa parte das redes brasileiras, datacenters e VPNs, devolvendo 451. Por isso o projeto aponta para data-api.binance.vision, o endpoint oficial de market data, que tem o mesmo contrato e não é bloqueado. Se alguém trocar essa URL no appsettings.json, é aqui que quebra.

07 — próximo passoConectar sua conta

"Cadastrar uma corretora" na ApiCripto e "conectar sua conta da Binance" são duas coisas diferentes, e vale separar antes de sair criando chave.

Preço de mercadoSua conta
RespondeQuanto vale o BTC agoraQuanto de BTC você tem
Precisa de chaveNãoChave + secret, com assinatura
Hostdata-api.binance.visionapi.binance.com
Na ApiCriptoFuncionandoAinda não

O que existe hoje é a coluna da esquerda: a API lê preço público, sem nenhuma credencial. Ler saldo e posições é a coluna da direita, e exige três coisas que o projeto ainda não tem.

1. Assinar cada requisição

Os endpoints de conta pedem um HMAC-SHA256 da query string inteira, usando o secret como chave, mais um timestamp em milissegundos e o cabeçalho X-MBX-APIKEY. Requisição sem assinatura é recusada com -1102 Mandatory parameter 'signature' was not sent.

2. Trocar de host

O data-api.binance.vision devolve 404 em /api/v3/account — ele é market data e nada mais. Endpoint de conta só existe no api.binance.com e no ambiente de testes testnet.binance.vision, e os dois estão sujeitos ao bloqueio regional que o projeto evitou de propósito.

3. Guardar o segredo fora do código

Chave e secret nunca entram no appsettings.json: esse arquivo é versionado, e o repositório é público. O lugar certo em desenvolvimento é o User Secrets do .NET, que grava fora da pasta do projeto, no perfil do usuário — impossível commitar por acidente.

terminalApiCripto/ApiCripto
dotnet user-secrets init
dotnet user-secrets set "Binance:ApiKey" "sua-chave"
dotnet user-secrets set "Binance:ApiSecret" "seu-secret"

A leitura no código não muda nada: IConfiguration junta o appsettings.json e os user secrets na mesma árvore, então _config["Binance:ApiKey"] funciona igual — só que o valor vem de fora do repositório.

Comece pelo testnet

O testnet.binance.vision tem o mesmo contrato da API real, com chave de brincadeira e saldo fictício. Dá para desenvolver e demonstrar a funcionalidade inteira sem nenhuma credencial da sua conta de verdade encostando num projeto escolar público. Quando for para a conta real, use uma chave marcada apenas como leitura, sem permissão de saque nem de ordem, e com o seu IP na whitelist.
