ApiCripto por dentro

Uma API REST que cadastra corretoras e ativos de criptomoeda e preenche o histórico de cotações com preços reais puxados da API pública da Binance. Este documento é o mapa para mexer no código daqui a seis meses, quando o motivo de cada decisão já tiver saído da cabeça.

Seção 4As camadas e o fluxo de uma requisição

Cada camada só conhece a de baixo, e a conversa acontece sempre por interface, nunca por classe concreta. É isso que permite trocar o banco, trocar a corretora ou testar um service sem subir a API inteira.

1 · entrada Controller Lê a rota e a query, chama o service, escolhe o status HTTP. Nenhuma regra aqui. controllers/
2 · decisão Service Valida regras de negócio e orquestra. Não conhece HTTP nem EF Core. services/
3 · dados Repository Monta as consultas LINQ e salva. Única camada que enxerga o DbContext. repositories/
4 · persistência EF Core → SQLite Traduz LINQ em SQL e grava no arquivo apicripto.db. infra/AppDbContext.cs
lateral · terceiro BinanceClient Só nos endpoints de sincronização: o service chama a Binance por HTTP e traduz o JSON para Cotacao. integracoes/

O caminho de GET /api/ativo?corretoraId=1&precoMin=1000

  1. O ASP.NET mapeia a query string para um objeto AtivoFiltro (graças ao [FromQuery]).
  2. AtivoController.Listar repassa o filtro para IAtivoService.
  3. AtivoService não tem regra nesse caminho e delega ao repositório.
  4. AtivoRepository.ListarAsync encadeia um Where por filtro preenchido e só então executa ToListAsync().
  5. O EF gera um único SELECT com todos os WHERE e o JOIN da corretora.
  6. O controller devolve 200 com a lista serializada em JSON.
Por que tanta camada

Em um CRUD pequeno isso parece cerimônia. O retorno aparece na manutenção: trocar SQLite por PostgreSQL mexe em uma linha do Program.cs; trocar a Binance por outra corretora mexe em um arquivo de integracoes/. Sem as camadas, os dois seriam um find & replace no projeto inteiro.

Por que os dois relacionamentos apagam de formas diferentes

Não é inconsistência, é intenção. Corretora → Ativo usa Restrict: apagar uma corretora com ativos destruiria em silêncio todo o histórico de preços, então o banco recusa e o CorretoraService devolve 400 com o motivo. Ativo → Cotacao usa Cascade: uma cotação não significa nada sem o ativo dela, e sobreviver ao pai só produziria linhas órfãs.

Os campos espelho do Ativo

UltimoPreco, Variacao24h e AtualizadoEm são uma cópia da última cotação, guardada dentro do Ativo. É desnormalização proposital: sem ela, o filtro de faixa de preço teria que rodar sobre um subselect na tabela de cotações em toda listagem.

O preço dessa escolha é o risco de os dois divergirem. A defesa é ter um único ponto de escrita:

services/CotacaoService.csúnico lugar que grava Cotacao
public async Task<Cotacao> RegistrarAsync(Ativo ativo, Cotacao cotacao)
{
    cotacao.AtivoId = ativo.Id;
    await _repository.AdicionarAsync(cotacao);

    // só promove a "último preço" se for de fato a mais recente —
    // sem isso, importar histórico antigo faria o preço voltar no tempo
    if (ativo.AtualizadoEm is null || cotacao.CapturadoEm >= ativo.AtualizadoEm)
    {
        ativo.UltimoPreco  = cotacao.Preco;
        ativo.Variacao24h  = cotacao.Variacao24h;
        ativo.AtualizadoEm = cotacao.CapturadoEm;
        await _ativoRepository.AtualizarAsync(ativo);
    }

    return cotacao;
}
Regra de manutenção

Toda gravação de cotação — manual, sincronizada ou de um fluxo futuro — passa por RegistrarAsync. No dia em que alguém inserir uma Cotacao direto pelo repositório, o UltimoPreco começa a mentir e os filtros de preço passam a devolver resultado errado sem erro nenhum aparecer.

Seção 6Como os filtros funcionam

Os seis filtros são opcionais, combináveis entre si (AND) e chegam pela query string. Nenhum deles filtra em memória: tudo vira WHERE no SQL.

FiltroQuery stringVira em SQL
Por corretora?corretoraId=1igualdade na FK
Por símbolo (parcial)?simbolo=btcLIKE '%BTC%'
Por tipo?tipo=Stablecoinigualdade no enum
Preço mínimo?precoMin=1000UltimoPreco >= 1000
Preço máximo?precoMax=5000UltimoPreco <= 5000
Monitorado?monitorado=trueigualdade no bool
Extras de apresentação: ?ordenarPor=preco|variacao|simbolo e ?desc=true
repositories/AtivoRepository.csListarAsync
var query = ComRelacionamento().AsNoTracking();   // nada foi ao banco ainda

if (filtro.CorretoraId.HasValue)
    query = query.Where(a => a.CorretoraId == filtro.CorretoraId.Value);

if (!string.IsNullOrWhiteSpace(filtro.Simbolo))
{
    var termo = filtro.Simbolo.Trim().ToUpperInvariant();
    query = query.Where(a => a.Simbolo.Contains(termo));
}

// ... demais filtros ...

return await query.ToListAsync();                // AQUI vai UM SELECT ao banco

O truque é o IQueryable: cada Where só acrescenta um nó na árvore de expressão. A consulta continua sendo montada em memória e só é traduzida para SQL no ToListAsync(). Se em vez disso o código fizesse .ToList() antes dos Where, o banco devolveria a tabela inteira e o filtro aconteceria no C# — funciona com 7 ativos, derruba a aplicação com 700 mil.

A busca por símbolo é case-insensitive por construção, não por sorte: o AtivoService grava todo símbolo em maiúsculas e o filtro compara com o termo também em maiúsculas. Assim o resultado não depende do collation do banco, que muda entre SQLite e PostgreSQL.

Seção 7A integração com a Binance

A API consome GET /api/v3/ticker/24hr?symbol=BTCUSDT — endpoint público, sem chave de API. A responsabilidade fica dividida em três peças com fronteiras nítidas:

PeçaResponsabilidade únicaNão sabe
BinanceClientFalar HTTP com a Binance e traduzir falha em mensagemo que é um Ativo
SincronizacaoServiceDecidir o que sincronizar e traduzir o DTO externo em Cotacaocomo o HTTP foi feito
CotacaoServiceGravar e manter os campos espelho consistentesque a Binance existe

Os números chegam como texto

A Binance devolve "lastPrice": "78705.99000000" — string, não número, para não perder precisão em linguagens que só têm double. A conversão acontece num único arquivo e sempre com InvariantCulture: em uma máquina configurada em pt-BR, o parse padrão leria o ponto como separador de milhar e transformaria 78.705,99 em 7.870.599.

integracoes/BinanceTicker24hDto.csfronteira com o mundo externo
private static decimal ParaDecimal(string valor) =>
    decimal.TryParse(valor, NumberStyles.Any, CultureInfo.InvariantCulture, out var r)
        ? r
        : 0m;

Falha de rede não é bug

ObterTicker24hAsync nunca lança exceção para quem chama: devolve (Ticker, Erro). Um terceiro fora do ar é resultado esperado de uma integração, e cada tipo de falha vira uma mensagem que o usuário da API entende:

SituaçãoResposta da APIMensagem
Símbolo que a Binance não conhece502"A Binance não reconhece o símbolo 'FAKEUSDT'."
Bloqueio por região (HTTP 451)502orienta a trocar a BaseUrl
Limite de requisições (HTTP 429)502"tente de novo em alguns segundos"
Timeout ou sem rede502"não foi possível alcançar a Binance"
Corretora sem CodigoIntegracao400orienta a lançar a cotação manualmente
Ativo inexistente404"Ativo 999 não encontrado."

502 Bad Gateway é o status certo quando esta API está de pé mas o serviço do qual ela depende falhou. 500 diria "o bug é meu"; 400 diria "a culpa é do cliente". A distinção entre os três está toda no switch do SincronizacaoController, alimentado pelo enum StatusSincronizacao.

Configuração

appsettings.json
"Binance": {
  "BaseUrl": "https://data-api.binance.vision",
  "TimeoutSegundos": 15
}
Por que não api.binance.com

O host principal da Binance responde HTTP 451 (bloqueio por região) em várias redes, datacenters e VPNs — inclusive no ambiente onde esta API foi testada. O data-api.binance.vision é o endpoint público oficial de market data: mesmo contrato, sem chave, sem bloqueio geográfico. Se a rede onde o projeto rodar liberar o host principal, é só trocar a BaseUrl.

Sincronização em lote é sequencial de propósito

SincronizarTodosAsync percorre os ativos em foreach, um de cada vez. Trocar isso por Task.WhenAll parece uma otimização óbvia e quebra duas coisas ao mesmo tempo: a Binance limita requisições por IP (vira 429) e o DbContext do EF Core não é thread-safe — duas gravações concorrentes no mesmo contexto lançam exceção. Se um dia forem milhares de ativos, o caminho é uma fila com BackgroundService, não paralelizar em cima do mesmo contexto.

Falha em um símbolo não aborta o lote: cada item entra no relatório com sucesso: false e o motivo, e a resposta é sempre 200 com o resumo.

Três detalhes de contrato que valem a pena notar:

  • A cotação vive em rota aninhada — /api/ativo/3/cotacao — porque ela não existe fora de um ativo, e a URL deve dizer isso.
  • Sincronizar é POST, não GET: cada chamada insere uma linha. GET, por contrato HTTP, não pode ter efeito colateral e pode ser cacheado por qualquer proxy no caminho.
  • Histórico de ativo inexistente devolve 404; ativo que existe mas ainda não tem cotação devolve 200 com []. São situações diferentes e o cliente precisa distinguir.

Seção 9Decisões e trade-offs

Cada linha aqui é uma escolha que poderia ter sido outra. A coluna da direita é a que importa daqui a seis meses: o sinal de que chegou a hora de mudar.

DecisãoPor quêReveja quando…
SQLite em arquivo Zero setup: git clone + dotnet run e funciona na máquina de quem for avaliar …precisar de acesso concorrente de escrita ou de rodar em servidor
Database.Migrate() na subida O banco nasce pronto sem passo manual …for para produção — lá a migration é passo separado do deploy, com backup
Campos espelho no Ativo Filtro de preço vira WHERE simples e indexável …precisar de mais agregados (média 7d): aí é view ou tabela de resumo
DTOs só de entrada Impede over-posting: o cliente não consegue mandar Id nem preço …a resposta precisar esconder campos — aí entram DTOs de saída também
[JsonIgnore] em Ativo.Cotacoes Histórico cresce sem limite; embutir na listagem faria payloads gigantes …nunca. Se precisar do histórico, use o endpoint dedicado
Tupla (resultado, erro) nos services Distingue "não achei" (404) de "achei mas não pode" (400) sem exceção de fluxo …os casos passarem de três — aí um Result<T> próprio paga o custo
Swagger ligado sempre É projeto acadêmico: a banca precisa abrir e testar …for para produção — aí volta para dentro do if (IsDevelopment())
Sem autenticação Fora do escopo do trabalho …qualquer exposição fora do localhost

Seção 10Receitas de manutenção

Adicionar um filtro novo no Ativo

  1. Crie a propriedade opcional em dtos/AtivoFiltro.cs.
  2. Acrescente um if (filtro.X.HasValue) com o Where correspondente em AtivoRepository.ListarAsync.
  3. Pronto. Controller, service e Swagger se atualizam sozinhos — o [FromQuery] mapeia a propriedade nova automaticamente.

Adicionar um campo em uma entidade

  1. Adicione a propriedade no arquivo de models/.
  2. Se ele deve poder ser enviado pelo cliente, adicione também no DTO de entrada e no mapeamento dentro do service.
  3. dotnet ef migrations add AdicionaCampoX e rode o projeto — o Migrate() aplica na subida.
  4. Se o campo for obrigatório e a tabela já tiver linhas, defina um valor padrão na migration, senão o SQLite recusa.

Plugar uma segunda corretora (ex.: Mercado Bitcoin)

  1. Crie integracoes/MercadoBitcoinClient.cs com a mesma forma de retorno (Ticker, Erro).
  2. Registre o typed client no Program.cs com AddHttpClient.
  3. No SincronizacaoService, escolha o cliente pelo Corretora.CodigoIntegracao — hoje há uma constante "BINANCE"; com dois ou mais, o padrão indicado é um dicionário de codigo → cliente injetado.
  4. Cadastre a corretora com o CodigoIntegracao novo. Nenhuma outra camada muda.

Migrar de SQLite para PostgreSQL

  1. dotnet add package Npgsql.EntityFrameworkCore.PostgreSQL.
  2. No Program.cs, troque UseSqlite por UseNpgsql.
  3. Troque a connection string em appsettings.json.
  4. Apague o bloco if (Database.IsSqlite()) do AppDbContext: no Postgres decimal é nativo e a conversão para double só faria perder precisão.
  5. Apague a pasta Migrations/ e gere de novo — migrations são específicas do provedor.

Atualizar preços sozinho, sem chamar o endpoint

  1. Crie uma classe herdando de BackgroundService.
  2. Dentro do ExecuteAsync, abra um IServiceScope a cada ciclo — o ISincronizacaoService é Scoped e não pode ser injetado direto num serviço Singleton.
  3. Registre com builder.Services.AddHostedService<...>() e deixe o intervalo no appsettings.json.

Seção 11Armadilhas conhecidas

1 · decimal no SQLite

O SQLite não tem tipo decimal: ele guarda como TEXT, e comparação de texto colocaria "9" > "10". Sem o conversor para double no AppDbContext, os filtros precoMin/precoMax devolveriam resultado errado — e o EF só emite um warning, não um erro.

2 · Update() em objeto já rastreado

Chamar _context.Ativos.Update(ativo) num objeto que veio de uma consulta da mesma requisição marca o grafo inteiro como alterado — inclusive a Corretora carregada pelo Include — e gera UPDATEs desnecessários. Por isso os repositórios só chamam Update quando o objeto está Detached.

3 · DbContext não é thread-safe

Vale para qualquer tentação de paralelizar: Task.WhenAll sobre operações que compartilham o mesmo DbContext lança InvalidOperationException em produção e passa despercebido em teste pequeno.

4 · HTTP 451 da Binance

Se a sincronização começar a devolver 502 com mensagem de bloqueio por região, não é bug no código: é a rede. Confira a Binance:BaseUrl no appsettings.json.

5 · O seed só roda uma vez

DbSeeder.Seed começa com if (context.Corretoras.Any()) return;. Mudar os dados iniciais não tem efeito nenhum enquanto o apicripto.db existir — apague o arquivo para ver a mudança.
